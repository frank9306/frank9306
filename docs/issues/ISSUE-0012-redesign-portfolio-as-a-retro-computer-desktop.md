The owner requests a complete replacement of the site's previous design and interface copy with a retro computer desktop: windows, folders and a menu bar, projects presented as applications, and articles as documents. On 2026-11-04 the owner twice selected the same colorful Windows-style reference, replacing the earlier proposed Macintosh direction. Visitors should learn about Frank through exploration. ## Desired outcome

A coherent, bilingual retro desktop portfolio with useful window interactions, real project and article destinations, readable documents, and an equally usable mobile layout. Replace the visual world and interface wording while preserving verified personal/project facts and existing behavior contracts. The accepted plan and owner decision are maintained on [FRA-24](/FRA/issues/FRA-24#document-plan), pinned to revision `9d56f118-cfcc-4ba7-9bb1-8e8f9af412c9`; this Issue owns implementation scope and acceptance rather than duplicating that plan. The current implementation directive supersedes the accepted document's historical planning-only stage language, not its behavior or scope contracts.

## Accepted scope

- Rebuild the shell, homepage, projects page and not-found presentation; rewrite visible Chinese/English interface copy and relevant page metadata. Preserve `/`, `/projects`, navigation history and direct entry.
- Desktop: follow the owner-selected reference with a teal desktop, navy title bars, gray beveled window frames/buttons, colorful pixel icons, a bottom taskbar and an original pixel-art desk illustration. Include a menu bar, application/folder shortcuts, an initial about document, project browser, notes shortcuts and contact document.
- Implement the accepted interaction revision: working Start menu and taskbar, open/focus/minimize/restore/maximize/close windows and bounded desktop dragging, with keyboard/touch alternatives. Use a contact shortcut instead of a fake recycle bin; do not invent an online availability signal. Keep the project location read-only and every repository action tied to an explicit project.
- Use existing GitHub filtering, ordering, cache and fallback behavior. Preserve the initial four / expanded maximum ten project behavior. Keep explicit repository links inside project details.
- Present real knowledge-site articles as document shortcuts with visible external-destination cues. Keep reading on the existing knowledge site; no iframe, content mirroring or new content API is proposed.
- Mobile: a compact launcher and one readable foreground window, normal page scrolling, reachable controls, no requirement to drag or double-click.
- Apply Impeccable product-context/design gates and the repository's module design, TDD, review and browser verification requirements within the accepted plan. Keep inferred audience assumptions distinct from verified identity and project facts.
